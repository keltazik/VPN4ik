# VPN4ik — Windows-клиент

Приложение на C#, WPF и .NET 8. Сохранены бордовая и золотая палитра и рисунок орнамента. Серверы находятся слева, управление подключением — справа. Прозрачные области орнамента не ловят нажатия; прокрутка и элементы интерфейса оформлены общей темой.

## Векторный орнамент

`docs/ornament/ornament.svg` содержит цветные кривые без встроенного растра. В приложении используется соответствующий `DrawingImage` из `source/VPNyan/VPNyan/Ornament.xaml`. Ресурс заморожен для повторного использования. Для нажатий используется отдельная замороженная геометрия силуэта `OrnamentHitGeometry`, полученная из прозрачности исходника: движение мыши не перебирает цветные детали. Границы замороженного источника вычисляются один раз, а не заново при каждом чтении `DrawingImage.Width/Height`. Для остальных векторных изображений `AlphaHitImage` поддерживает проверку залитых фигур с учётом прозрачности, трансформаций и обрезки.

Для плавного наведения геометрия рисуется в `BitmapCache` с запасом разрешения для увеличения до 1,04 и текущего DPI. Масштаб и свечение анимируются на родительском контейнере, вне кэшируемого содержимого: семь тысяч кривых не перерисовываются каждый кадр. При загрузке окна и смене DPI разрешение кэша уточняется, векторный источник сохраняется. Это штатный [механизм кэширования WPF](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.bitmapcache).

Это обводка исходной вышивки: мелкая текстура приближена цветными контурами. При масштабировании кривые не пикселизуются, но новых деталей исходного рисунка не возникает. Исходный `ornament.png` сохранён для воспроизводимости и больше не включается в ресурсы приложения.

Для повторной генерации нужны Python, VTracer 0.6.15 и Pillow 12.3.0, только на машине разработчика:

```powershell
python -m pip install --target .tools/vectorizer vtracer==0.6.15 Pillow==12.3.0
python tools/vectorize_ornament.py
```

Скрипт одновременно обновляет SVG и WPF-ресурс из одного набора кривых. Клиенту VTracer, Python или библиотека SVG не требуются.

## Запуск и подключение

Готовая автономная сборка: `artifacts\VPN4ik-routing\VPNyan.exe`. Она содержит .NET Runtime; для переноса нужна вся папка `VPN4ik-routing`. Перед запуском новой версии закрой старое окно.

1. Нажми значок плюса в квадрате на постоянной левой панели («Добавить»).
2. Вставь HTTPS-ссылку подписки и нажми «Импортировать», либо выбери файл `.conf`, `.json` или `.txt`.
3. Вернись к серверам, выбери сервер и нажми на видимую часть орнамента.
4. Разреши запрос Windows на создание VPN-адаптера. Повторное нажатие отключает VPN.

Подписки и ранее выбранный сервер сохраняются между запусками. Поиск работает по названию и протоколу. Обновление заменяет серверы выбранной подписки без дублей; при ошибке прежний список остаётся. Поддерживаются JSON-конфигурации Xray, текстовые и base64-списки ссылок. Название профиля не определяет его протокол: он читается из самой конфигурации.

## Движок и проверка соединения

В сборку включён официальный **Xray-core 26.10.21** с собственным TUN для Windows и подписанным драйвером Wintun. Архив скачивается только из официального релиза и проверяется SHA-256; хеши `xray.exe` и `wintun.dll` проверяются перед запуском. Лицензии находятся в папке `Engine`.

Окно приложения работает без повышения прав. Отдельный скрытый процесс запрашивает права только при подключении, создаёт адаптер `VPN4ik-TUN`, настраивает маршруты IPv4/IPv6 и DNS. Канал управления ограничен ACL и взаимной проверкой PID и пути приложения. Одновременно разрешён один TUN-сеанс VPN4ik. Закрытие окна, потеря канала управления и выход родительского процесса приводят к остановке принадлежащего ему движка. При обычном отключении Xray получает Ctrl+C и очищает свои маршруты, DNS и фильтры.

Адрес сервера разрешается **до** включения TUN, чтобы не создавать цикл при первоначальном DNS-запросе. При наличии активного Ethernet/Wi-Fi с шлюзом исходящее соединение движка привязывается к физическому интерфейсу: другой уже работающий VPN не становится обязательным внешним каналом. Если подходящего интерфейса нет, используется автоматический выбор Xray. Параметры VLESS, TCP/gRPC, TLS и Reality сохраняются. Конфигурация запуска строится из разрешённых параметров протокола: произвольные скрипты, переменные окружения, пути к файлам и сторонние слушатели из подписки не исполняются. Секреты передаются в память и stdin движка; открытый временный JSON на диск не записывается.

Статус «Подключено» появляется после проверки работающего движка, адаптера и системного маршрута, HTTPS-запроса через выбранный прокси и HTTPS-запроса через системную сеть с совпадением внешнего IP. Используется `https://api.ipify.org`. Каждые 30 секунд проверка повторяется; если доступ не подтверждён, интерфейс сообщает об этом. При раздельном туннелировании системный внешний IP может отличаться от IP прокси: проверяются работающий движок, маршрут TUN и доступ через выбранный прокси. Скорость и объём VPN-трафика берутся из 64-битных счётчиков outbound proxy самого Xray, а для WireGuard — из счётчиков адаптера.

Для предоставленной подписки проверены реальные подключения через gRPC/Reality (Латвия), TCP/Reality (Швеция) и gRPC/TLS (Нидерланды), включая отключение и удаление маршрута VPN4ik. Отдельно проверен полный путь через окно приложения: статус, журнал и запись настоящего сеанса в историю.

WireGuard `.conf` по-прежнему поддерживается отдельной службой. Для него надпись «Туннель WireGuard запущен» подтверждает состояние службы; handshake не выдаётся за проверенный. Расширенные параметры XHTTP и маскировка Hysteria2 пока не поддерживаются: приложение сообщает об ограничении явно. Полноценный Kill Switch, восстановление после сна и обновление приложения остаются отдельными задачами.

## Меню, настройки и журнал

Слева всегда видна панель иконок: серверы, добавление конфигурации, настройки, логи и история. Верхняя стрелка плавно разворачивает подписи или оставляет только иконки. Панель занимает свою колонку и не перекрывает содержимое; её состояние сохраняется. Разделы открываются в том же окне, при переходе выбранная иконка подсвечивается. Всплывающая подсказка орнамента отключена.

Настройки сохраняют и применяют автозапуск Windows, запуск свёрнутым, сворачивание в трей, автоматическое подключение к последнему серверу, уведомления и MTU (1280–1500, со следующего подключения). Переключатели сохраняются сразу после нажатия, корректное значение MTU — при вводе. Незавершённый или неверный MTU не перезаписывает последнее корректное значение; ошибка показывается рядом. Кнопки сохранения нет. Иконка трея позволяет открыть окно, подключиться, отключиться и выйти.

Настройки разделены на «Основные», «Соединение», «Маршрутизация» и «Интерфейс». Кроме прежних параметров доступны собственные DNS-серверы (от 1 до 4 IP), прямой доступ к локальной сети, единицы скорости Mbps/MB/s, фоновая проверка TCP-пинга и её интервал 30/60/120 секунд. Кнопки подсвечиваются только фоном; у закрытия окна фон красный. Подсказка фокуса при навигации клавиатурой сохранена.

Раздельное туннелирование работает с профилями Xray: режим «Выбранное без VPN» направляет совпавшие приложения, домены и IP/CIDR напрямую, остальное — через VPN; режим «Только выбранное через VPN» делает обратное. Правила разных списков объединяются по ИЛИ, доступ к локальной сети имеет приоритет, когда включён. Можно выбрать .exe через проводник или ввести имена процессов/полные пути (регистр важен). Домен включает поддомены; ECH может скрыть имя сайта, для таких случаев есть правила по процессу/IP. Параметры маршрутизации, DNS и MTU применяются при следующем подключении. Пустой режим Include можно сохранить во время настройки, но он не запустит соединение до добавления правила. Для WireGuard маршрутизация определяется AllowedIPs импортированного файла.

Статистика Xray считывается через существующий SOCKS-вход с паролем; отдельного открытого HTTP/API-порта нет. Правила маршрутизации не распространяются на служебный запрос проверки выбранного прокси. Прямые исключения не увеличивают счётчик VPN. Скорость обновляется раз в секунду по монотонному времени, с начальной точкой отсчёта после подключения; сброс счётчиков не создаёт отрицательных значений или скачков. Проверка доступности каждые 30 секунд не задерживает обновление скорости.
История содержит реальные попытки, подтверждённые подключения, время и результат завершения. Незавершённый после аварийного закрытия сеанс помечается «Прервано» без выдуманного времени отключения. В журнале сохраняются события приложения и сообщения движка; UUID, пароли, ключи, служебные пути и ссылки подписок скрываются.

Подписки и полный JSON профилей хранятся в `%LOCALAPPDATA%\VPN4ik\subscriptions.dpapi`, журнал и история — в `activity.dpapi`. Оба файла защищены Windows DPAPI для текущего пользователя. В настройках выбранный профиль содержит хеш URL. Импортированные WireGuard `.conf` пока хранятся открыто в той же папке. Ссылка владельца не встроена в код или бинарный файл.

## Проверка задержки серверов

Измеряется TCP-пинг до фактического порта сервера: до шести проверок параллельно, результаты в миллисекундах появляются по мере готовности. TCP-соединение ограничено 1,2 секунды, DNS и попытки адресов одного профиля — 1,8 секунды, группа из 24 профилей — шестью секундами. Проверка не запускает Xray и не меняет маршруты. ICMP не используется, потому что серверы могут его блокировать.

При активном VPN/TUN проверка разрешена, включая фоновый таймер и диагностический режим. Собственное соединение и активные адаптеры Happ, Wintun, WireGuard и других TUN-клиентов помечают замер как потенциально неточный: перед числом появляется ≈, а подсказка объясняет влияние маршрутизации. Ручной запуск показывает неблокирующее предупреждение и продолжает TCP-проверку. Автоматическая проверка не показывает всплывающих сообщений. Обычный Ethernet и виртуальная LAN Radmin VPN не требуют такого предупреждения. Сама проверка не отключает VPN и не меняет маршруты.

Проверка автоматически запускается с выбранным интервалом, в том числе при активном VPN; кнопка со шкалой запускает её вручную независимо от автопроверки. Число ms обозначает TCP-задержку до порта, а не проверку VPN-авторизации. Если ответ не получен, показывается нейтральное «Нет замера». Кнопка выбора сервера предпочитает минимальный свежий TCP-пинг. Статус подключения подтверждается отдельной проверкой движка и сети.

В списке серверов показываются круглые векторные флаги. Страна берётся из явного эмодзи, названия страны или отдельного кода в имени профиля, без обращения к сервисам геолокации IP; явный флаг имеет приоритет. Для неизвестного названия используется нейтральный глобус. Исходное имя профиля сохраняется. Подсказки полей используют `AutomationProperties.HelpText`, а `Tag` остаётся служебным признаком типа правила: `ip`, `domain`, `process` и `dns` не отображаются как текст. Подсказки и введённые строки расположены слева сверху; пример CIDR не добавляется в правила автоматически.
## Режимы подключения и DNS (beta.7 local.1)

На главной странице доступны «Прокси» и «Xray TUN». В прокси-режиме Xray слушает HTTP только на 127.0.0.1, а отдельный служебный SOCKS-вход сохраняет случайную авторизацию. Дочерний процесс без повышения прав временно применяет системный HTTP/HTTPS-прокси и восстанавливает прежние ProxyEnable/ProxyServer/ProxyOverride/AutoConfigURL при выходе, потере канала или завершении родителя. Предыдущее состояние сохраняется в proxy-restore.dpapi для восстановления после аварии. Изменённый другим приложением сервер прокси не перезаписывается. UDP и правила по процессам требуют TUN; программы, игнорирующие системный прокси, в прокси-режиме не туннелируются.

TUN выдаёт Windows внутренний DNS 172.31.255.2. Правило для порта 53 направляет запросы в DNS-outbound Xray; встроенный DNS использует TCP-резолверы через выбранный прокси, кеш и резервный сервер. Заводская пара 1.1.1.1 / IPv6 Cloudflare мигрирует в 1.1.1.1 / 1.0.0.1, только если совпадает целиком; собственные DNS не заменяются. A и AAAA обрабатываются встроенным DNS, для остальных типов возвращается пустой успешный ответ по умолчанию Xray. Режим локального DNS использует localhost-резолвер Xray, который при autoOutboundsInterface пропускает DNS собственного TUN; запросы могут идти напрямую.

Нативная проверка заменяет только TUN-вход loopback UDP-слушателем, сохраняя DNS-правила приложения. Клиент UDP получает A/AAAA через TCP-only DNS-сервер; отдельно проверяется HTTP-прокси. Режим проверок `--verify-provider-dns <subscriptions.dpapi> <report.json>` проверяет DNS и загрузку публичных страниц для профилей Латвии, не создаёт TUN и не изменяет системный прокси. В отчёте нет адресов серверов, ключей и ссылок подписки.
## Сборка и проверки

Локальная сборка 6: проверка доступности использует несколько HTTPS-адресов с задержкой старта резервных запросов 300 мс и ограничением каждой попытки 8 с. Проверенный ответ 204 допускает подтверждение доступа без внешнего IP. Первая неудачная фоновая проверка переводит интерфейс в перепроверку; повторная показывает ошибку, сохраняя работающий движок. Проверка реального завершения движка остаётся отдельной.

Системная HTTPS-проверка полного TUN проверяет `GetBestInterfaceEx` для адреса сокета до и после подключения. Внешние IP независимых запросов не обязаны совпадать. В диагностике SOCKS используется физический интерфейс, чтобы результат не зависел от другого установленного VPN. Для изолированной проверки серии подключений доступен режим `--verify-connection-series <subscriptions.dpapi> <report.json> <index>`: отчёт не содержит адресов или ключей, подробный журнал защищён DPAPI. Этот режим не включает TUN. Не добавлять диагностические DPAPI-файлы и пользовательские подписки в Git.

Из корня проекта, с установленным .NET SDK:

```powershell
powershell -NoProfile -File build.ps1
powershell -NoProfile -File checks\run.ps1
powershell -NoProfile -File checks\run.ps1 -NativeRouting
```

При отсутствии движка `build.ps1` запускает `scripts\bootstrap-engine.ps1`: он загружает закреплённый официальный релиз, проверяет хеш архива и подпись Wintun. Сборка публикуется автономно для Windows x64. Перед пересборкой закрой экземпляр приложения из целевой папки. Другую папку можно задать через `-OutputDirectory`.

Локальные проверки используют .NET 10 и отдельный каталог данных внутри `.checks-data`; не изменяют автозапуск, пользовательские профили и маршруты, не устанавливают туннели. Проверяют импорт, защиту хранилища, подготовку безопасной конфигурации движка, историю, журнал, настройки, навигацию, поиск, маску нажатий и размеры окна. Снимки интерфейса создаются в `.checks-data`. Режим -NativeRouting отдельно проверяет настоящий Xray на локальных HTTP-серверах через SOCKS, оба режима маршрутизации, процессы/домены/IP и статистику; использует только loopback, без TUN, повышения прав или внешних запросов. Проверки внешних серверов выполняются отдельно через диагностический режим приложения.

Старый `VPN4ikSetup.exe` не обновлён; `source/VPN4ik.iss` требует переработки перед выпуском установщика. Название проекта и исполняемого файла в исходниках остаётся VPNyan. Оригинальный архив сохранён; встроенные в него старые приватные конфиги не являются действующей инфраструктурой и не включаются в приложение.

Официальные источники: [Xray-core 26.10.21](https://github.com/XTLS/Xray-core/releases/tag/v26.10.21), [TUN Xray](https://github.com/XTLS/Xray-docs-next/blob/main/docs/en/config/inbounds/tun.md), [форматы Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/examples-of-links-and-parameters.md), [WireGuard Windows](https://github.com/WireGuard/wireguard-windows/blob/master/docs/enterprise.md).



## Импорт смешанных подписок (beta.2)

Парсер распознаёт Xray Hysteria2 с `protocol: hysteria`, `settings.address/port/version` и `streamSettings.hysteriaSettings.auth`, а также ссылки hy2:// и hysteria2://. Клиент сохраняет TLS и QUIC-параметры из разрешённого набора. Серверные функции, файловые пути, маскировка и произвольные настройки из подписки в повышенный процесс не передаются. Служебные профили freedom/blackhole/dns пропускаются; некорректные профили по-прежнему отклоняются. UDP-серверы помечаются UDP, TCP-пинг к ним не отправляется.

Для воспроизводимой проверки ответа провайдера доступен режим проверок `--provider-response <response.dpapi> <report.json>`. Исходный ответ защищается Windows DPAPI и остаётся в .checks-data; отчёт содержит только счётчики, протоколы и обезличенные ошибки. Команда проверяет сформированные конфигурации настоящим Xray без TUN и не является подтверждением подключения к каждому серверу. Учётные данные Hysteria2 скрываются в журнале.

## Управление серверами (beta.3)

`MainWindow.Servers.cs` хранит список источников и выполняет удаление, сортировку и переключение. Удаление профиля оставляет его ID в `DeletedProfileIds`, чтобы обновление подписки не возвращало тот же профиль. Повторный импорт после удаления всего источника создаёт его заново. WireGuard удаляется только из собственного каталога приложения; исходный выбранный файл вне каталога не затрагивается.

`MainWindow.Actions.cs` содержит меню сервера, встроенные окна редактирования/подтверждения, выбор процессов и сброс. Список процессов читает имя и, когда доступен, путь EXE без повышения прав. Полный сброс останавливает собственное соединение, отменяет замеры, отключает автозапуск и очищает хранилище. Удаление файлов не является гарантированным стиранием данных с диска.

`IVpnSession` позволяет проверять переключение изолированно: второй сеанс создаётся только после завершения `DisposeAsync` первого; повторный запуск во время перехода блокируется. Ошибка остановки сохраняет старый сеанс и выбор, ошибка запуска нового оставляет приложение отключённым. Тесты используют отдельный каталог, не создают трей и не меняют реестр или маршруты. Дополнительно проверяется, что отложенные сообщения старого сеанса не возвращают логи после сброса.

Иконка хранится в `Assets/VPN4ik.ico`, используется ресурсом окна, PE-иконкой и в `NotifyIcon`. Генератор в `checks/IconGenerator.cs` рисует векторный знак и сохраняет размеры 16–256 px; режим `--generate-icon <path>` позволяет воспроизвести ресурс.

## Обновления приложения (включены в beta.6)

`ApplicationUpdates` читает публичный список [GitHub Releases](https://docs.github.com/en/rest/releases/releases#list-releases) без токенов. Проверка выполняется после запуска и каждые четыре часа, если включён переключатель в основных настройках. Ручная проверка работает независимо от него. Сравнение SemVer учитывает beta.10 после beta.9; опубликованные beta-выпуски предлагаются, черновики и обычные теги без релиза пропускаются. Ошибки фоновой проверки не прерывают VPN и не вызывают диалогов.

Скачивание начинается только по кнопке. Имя ZIP фиксировано: `VPN4ik-v<VERSION>-windows-x64.zip`. Автоустановка требует `digest: sha256:...` в [метаданных asset GitHub](https://docs.github.com/en/rest/releases/assets#get-a-release-asset), ожидаемый URL нашего репозитория, ограниченный размер и HTTPS-перенаправления только на известные хосты GitHub. Без SHA или при ошибке показывается ссылка на релиз. SHA подтверждает совпадение с опубликованным asset и не заменяет независимую подпись издателя.

Архив извлекается в случайный каталог `%TEMP%/VPN4ik-updates/`. Проверяются пути, дубликаты имён Windows, разрешённый список файлов, манифест, SHA EXE/Xray и версия PE. Новая программа выполняет `--verify-startup` в изолированном хранилище без VPN, трея и сети; требуется встроенная среда .NET. После подготовки собственный VPN штатно отключается. Копия текущего автономного EXE запускается скрытым вспомогательным процессом `--apply-update`, ожидает завершения конкретного родительского процесса и проверяет, что установленный EXE не изменился.

`UpdateInstaller` сначала сохраняет резервные файлы и подготавливает все замены рядом с целевыми файлами, затем заменяет их и повторно проверяет запуск. При ошибке восстанавливает прежние файлы; при невозможности полного отката сохраняет резервную копию для восстановления. Пользовательское хранилище, файлы настроек и конфиги отсутствуют в списке замен. Повышение прав для обновления не запрашивается; при недоступной записи предлагается GitHub. Завершённые и устаревшие каталоги подготовки очищаются при следующем запуске, без обхода ссылок файловой системы.

`UpdateChecks` проверяет поддельную ленту и архивы, запрет изменения пользовательских данных, порядок версий, отмену уведомления, автосохранение, ожидание завершения родителя и откат. Режим `--verify-updater <build-folder>` отдельно устанавливает настоящую переносимую сборку в изолированную копию, проверяет запуск WPF со встроенным runtime и откат после искусственной ошибки. `--check-update-feed` выполняет только чтение реальной публичной ленты, без скачивания или установки. Публикация релиза выполняется отдельно по запросу владельца; приложение и проверки её не выполняют.

## Смешанные списки ссылок (включены в beta.6)

Подписка может содержать серверные ссылки и отдельные deep-link строки маршрутизации другого клиента. Этот формат описан в [документации INCY](https://docs.incy.cc/subscription-format/) и [deep links](https://docs.incy.cc/deep-links/). `ParseDocument` распознаёт ограниченный набор префиксов: `incy://`, `happ://` и сокращённый `://` с командами `routing`, `autorouting`, `onadd`. Они исключаются из серверного списка, считаются в `IgnoredRoutingLines` и не исполняются. Payload и внешние URL не декодируются и не загружаются. Неизвестные команды и некорректные серверные ссылки остаются ошибкой, а подписка только с маршрутизацией не заменяет прежние серверы пустым списком.

Счётчик сохраняется с источником в DPAPI и сопровождается уведомлением в приложении: собственные правила VPN4ik сохраняются. Одинаковый разбор применяется к прямому тексту, внешней base64-обёртке и импорту из файла. Это совместимость со смешанным форматом, а не реализация всех deep links или маршрутизации INCY.

## Локальная интеграция zapret

`ZapretProfiles` читает установленную папку Flowseal и разбирает параметры запуска `winws.exe` из стратегий, не исполняя BAT-меню. Поддерживаются продолжения строк CRLF/LF, кавычки, `%BIN%`, `%LISTS%`, игровые диапазоны и экранированный литерал `^!`. Пути ограничены выбранным каталогом без файловых ссылок; служебные команды записи файлов и произвольные команды оболочки не принимаются. Проверена структура [Flowseal](https://github.com/Flowseal/zapret-discord-youtube), включая пользовательские списки, Game Filter и IPSet.

`ZapretNative` определяет процессы через Windows API по полному пути EXE и времени создания. Службы выбираются по проверенному ImagePath из этой же папки. Собственные процессы запускаются напрямую с массивом аргументов и скрытым окном, службы управляются через SCM. Остановка процесса освобождает его handles WinDivert; общий драйвер и сторонние сетевые службы не удаляются. При обнаружении другой установки запуск второго экземпляра блокируется. Возврат не создаёт дубликат, если zapret уже запущен вручную.

`ZapretController` выполняет привилегированное действие отдельным экземпляром приложения через именованный канал с SID ACL и взаимной проверкой PID/пути EXE. Основной GUI не получает права администратора. Запрос Windows вызывается по действию пользователя либо разрешённому им автоотключению. Отмена UAC сохраняет прежний режим, не подтверждённая остановка не позволяет начать VPN.

`MainWindow.Zapret.cs` хранит настройки, состояние вкладки и снимок запуска для возврата. Автоотключение по умолчанию false; без него соединение сопровождается предупреждением, без дополнительного диалога подтверждения. Смена серверов не восстанавливает zapret между туннелями. Окончательное отключение или ошибка запуска возвращают снимок, если включён соответствующий переключатель; ручное управление заменяет этот замысел только после успешного действия. Сам zapret работает независимо от окна VPN4ik.

Пользовательские списки сохраняются с задержкой и проверкой ввода. При отказе в записи доступна отдельная кнопка применения с правами администратора, чтобы набор текста не вызывал UAC. Пустые пользовательские списки записываются с безопасным нематчящим значением, а изменяемые файлы имеют резервные копии. Полный сброс VPN4ik очищает настройки интеграции, сохраняя внешнюю папку zapret.

`ZapretChecks` использует искусственную установку и подставные сеансы VPN; режим `--verify-zapret-processes` проверяет реальные операции Windows на тестовых процессах без WinDivert. Режим `--verify-zapret-folder <folder>` только читает стратегии и статус, а `VPNyan.exe --verify-zapret-status <folder> <report.json>` проверяет канал вспомогательного процесса действием status без повышения прав и изменений фильтров.

`ZapretDiscovery` при каждом запуске сразу из инициализации основного окна проверяет сохранённый путь, процессы/службы и обычные места распаковки. Автоподключение VPN ждёт этот этап. Обход локальных папок ограничен тремя уровнями, 4000 каталогами и восемью секундами, пропускает junction/symlink и системные папки; это поиск обычных установок, а не полный поиск по дискам. Кнопки повторного поиска и ручного указания доступны в разделе расположения, когда нет операции или несохранённых списков. Валидный сохранённый путь имеет приоритет; найденные варианты можно переключать. При отсутствии установки ручной раздел раскрывается автоматически.

Главный блок zapret содержит список полных BAT-имён и кнопки запуска/остановки/перезапуска. `ZapretProfiles.Read` проверяет разбор параметров до включения файла в список, исключая служебные BAT и неподдерживаемые операции. Текст статуса и инструкции расположены рядом с действиями; папка, фильтры и инструменты раскрываются отдельно. Поддерживаемые файлы по-прежнему не выполняются оболочкой: запускается winws с разобранными аргументами.

`OrnamentGlow` — отдельный кешируемый Image позади чёткого AlphaHitImage, с золотым DropShadowEffect и IsHitTestVisible=false. Анимация меняет только прозрачность: наведение, пульсация подключения, постоянное активное состояние и плавное затухание. DPI-кеш обновляется для обоих слоёв; повторное обновление контролов не перезапускает пульсацию. Геометрия и основной слой орнамента не размываются и не получают расширенный хитбокс.

Закрытый BAT ComboBox перехватывает PreviewMouseWheel и передаёт прокрутку внешнему ScrollViewer, сохраняя выбор; раскрытый список прокручивается обычным способом. Кнопки установки/удаления службы и её статус находятся в верхнем блоке. Статус использует ImagePath службы: точное совпадение разобранных аргументов определяет BAT, а при изменённых фильтрах доступно явно помеченное сохранённое имя. Это значение отделено от ещё не применённого выбора в ComboBox. Отсутствие или повреждение BAT не блокирует определение и остановку собственного процесса/службы. Снимок временной остановки сохраняет исходные команду и стратегию службы, тест стратегий возвращает её прежние метаданные.

«Открыть service.bat» — отдельное явное действие пользователя, исключение из встроенного управления без BAT-оболочки. Проверенный путь выбранной папки передаётся `cmd /d /v:off /s /c` с кавычками, `admin` и runas; открывается обычное интерактивное окно штатного менеджера. На старте VPN4ik эта команда не выполняется. Статус службы продолжает обновляться, пока вкладка открыта.

Настройка трея раскрывает независимые MinimizeToTray и CloseToTray. Новый CloseToTray по умолчанию false, старое значение MinimizeToTray сохраняется. Скрытие разрешено только при доступном ITrayHost; закрытие в трей не отключает VPN. Явный ExitApplication используется пунктом «Выход» и обновлением, сохраняет штатную очистку и работает даже из скрытого состояния. `TrayChecks` проверяет это на подставных трее и VPN без настоящего значка или изменения маршрутов.

`ProcessCatalog` читает путь EXE через QUERY_LIMITED_INFORMATION и после удаления дубликатов загружает иконки вне UI-потока. `ProcessIcons` преобразует системную иконку в замороженный BitmapSource и освобождает HICON через Dispose; для недоступных путей использует общий замороженный DrawingImage. Загрузка не выполняет EXE и не читает сетевые UNC-пути для иконок. Иконки временные, в правила маршрутизации попадает только путь либо имя процесса.

`MainWindow.Zapret.Tools.cs`, `ZapretMaintenance` и `ZapretServiceTools` реализуют пункты service.bat Flowseal 1.10.4 без выполнения его оболочки. Игровые порты допускают списки одиночных портов/диапазонов TCP и UDP и сохраняются при Enter или потере фокуса. Флаг `utils/check_updates.enabled` общий с service.bat, но VPN4ik сам проверяет версию при загрузке папки. Скачивания ограничены 1 МБ и 12 секундами, используют фиксированные адреса `.service` официального репозитория и проверяют формат. IPSet обновляется с сохранением none/any; новый список в этих режимах хранится для последующего loaded. Hosts показывается для ручного переноса, без автоматической замены системного файла. Fake-кандидаты берутся только из bin выбранной установки, ACTIVE-файлы резервируются.

Установка службы использует SCM и выбранные аргументы с автозапуском; занятое другой установкой имя `zapret` не перезаписывается. Удаление касается только проверенных ImagePath выбранной папки. Диагностика читает BFE, WinDivert, прокси, конфликтующие службы и TCP без «лечения» общих компонентов; TCP timestamps включаются отдельным явным действием. Диагностика service.bat дополнительно предлагает удалять чужие службы и чистить Discord — эти побочные действия намеренно не исполняются автоматически.

`ZapretStrategyTests` отделяет последовательность запуска/остановки от Windows и HTTP для проверок с подставными операциями. Настоящий тест разрешён только без активного VPN4ik и не более чем с одним экземпляром zapret в выбранной папке, ограничивает перебор 75 секундами, проверяет HTTPS YouTube/Discord с тайм-аутом 1,8 секунды параллельно и всегда пытается вернуть предыдущее состояние. Команды ранее установленной службы сохраняются до теста, возвращаются перед возобновлением; изначально выключенный экземпляр остаётся выключенным. Общий лимит канала — три минуты с учётом переходов SCM и восстановления. Другой системный VPN может влиять на результат HTTPS; тест его не выключает. Режим проверок `--verify-zapret-discovery` выполняет только чтение и показывает найденные установки.
